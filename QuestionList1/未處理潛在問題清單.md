## 問題分組與三階段生命週期（強制）

1. QuestionListx 管理編號 100 × (x − 1) + 1 至 100 × x；編號全域唯一、單調遞增，不因問題移動或刪除而重用。
2. 新問題分配下一個尚未使用的全域編號；#1–#100 歸 QuestionList1，#101–#200 歸 QuestionList2，依此類推。
3. 每組固定三份文件：未處理潛在問題清單.md、待測試清單.md、已修復紀錄.md。
4. 未處理 → 待測試：完整實作且有驗收條件；部分修補仍屬未處理。
5. 待測試 → 已修復：Relation Test PASS 且記錄環境、日期、步驟、結果及證據。
6. 待測試失敗或已修復回歸：以原編號返回未處理，保留來源與歷史紀錄。
7. 同一問題只能有一個有效狀態；跨清單移動不得更換 QuestionList 編號區間。
8. 每版檢查全部既存 QuestionList 的三份清單，並更新對應 PR 四份文件；無異動也要記錄。
9. 每次實作前先查閱相關開源專案與技術標準，於 Plan.md 記錄參考來源與取捨。
10. 新增程式碼遵循一致的 Google JavaScript Style Guide，維持既有 OCDA 模組邊界。
11. 全域共用屬性集中於全域屬性清單.md，不能繞過公開 API 改動其他物件私有狀態。
12. OMU LOOP 的相似 LOG 僅保留 START、ERROR、EHU、END；END 記錄處理數、壓縮數、錯誤數及耗時。
